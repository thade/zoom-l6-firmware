The Bridge is now 224 bytes, including eight 16-byte packets. Each packet carries
the immutable session ID, event kind and 64-bit absolute sample timestamp. Start
and stop timestamps are resolved at their original hook, before delivery can be
delayed across ring wraps. The worker never reinterprets an old modulo cursor.

Queue payloads are protected by one shared atomic gate. Producers attempt the
gate once; they do not wait for it to become free. Contention latches error 20
out-of-band. Full capacity or exhausted queue counters latch error 21. The worker
then cancels the optional file. This trades availability for explicit failure;
real contention frequency and instruction-level latency are unmeasured. No hook
performs file IO. A contended worker returns WAIT before copying audio or IO.
Atomic primitive implementation and hardware memory behavior still require audit.

The worker drains at most eight events per step and checks START -> ADMISSION ->
STOP ordering. Rejection, duplicates and unsupported order cancel the optional
capture. It copies directly from a claimed exchange slot into Capture and releases
the slot before file IO; the earlier serialized history buffer is not used in
this bridge. Worker entry exclusion prevents two callers entering the lifecycle.

Completion race
Hooks/publications reserve an active count before touching shared runtime state.
The high bit of that count closes admission atomically. Once readback succeeds,
the worker closes admission and waits for earlier reservations to return, then
checks the mailbox and error latch before exposing bridge_verified_path. Existing
reservations can still publish while admission is closing. Later arrivals do not
mutate queue or error state. The protocol assumes far fewer than 2^31 callers.

A rejection arriving during final read-close must still invalidate success.
life_revoke_quiesced changes an already VERIFIED lifecycle to FAILED and faults
Capture. It does not remove the closed file or undo its contents. Consumers must
use bridge_verified_path, not the underlying lifecycle path. No pad assignment
is performed, so no already-published assignment needs rollback in these tests.

Retirement contract -- not a device fence
bridge_retire_quiesced requires a terminal bridge, idle worker, no queue owner,
no active hook reservations and no READING exchange slots. Binding requires fresh
zeroed Bridge storage and a strictly increasing nonzero session ID; it rejects a
replacement while another bridge is bound and rejects rebinding old storage.
Wrong-session publications do not modify the current take.

These checks DO NOT establish safe reclamation or session handoff on hardware.
The caller must first stop all old hook/event sources, including stock queued
callbacks, and wait for in-flight accesses. A hook can load the global pointer
before reserving it; freeing that pointer needs the missing external fence.
Likewise an untagged old stock callback delivered after new binding could be
mistaken for a new-session event. Counters and session checks alone do not solve
that. The tests explicitly declare external quiescence and keep old storage alive.
Fresh binding is tested; complete second-take file/pool preparation is not.

New evidence (nine groups)
1. Actual hooked start/admission/stop delayed over multiple stock ring wraps
   produces exactly [64,704), 640 frames with the expected stereo payload.
2. Physical queue wrap preserves packet order.
3. Queue full and counter exhaustion produce detectable cancellation, no hook IO.
4. Duplicate and out-of-order events cancel.
5. Worker gate contention defers; producer contention latches cancellation.
6. A second worker cannot enter an occupied lifecycle.
7. Rejection during modeled audio write or final read-close removes eligibility
   and leaves no modeled open handles.
8. Completion waits for an injected outstanding hook reservation; admission is
   closed during that wait and success becomes visible only after it returns.
9. Premature/leased retirement is refused; externally quiescent retirement and
   fresh binding succeed, while stale explicit session tokens have no effect.

Test model and limits
Interleavings are explicit scheduling fixtures. For publication during IO, a
second emulator CPU receives a copy of Bridge state and returns only that state;
the worker's registers/stack and Capture/Life are not overwritten. Reservation
pause is injected into shared memory. This is useful protocol evidence, not a
complete hardware interrupt, cache or arbitrary preemption model. Original
instruction windows and compiled adapters run, but full DSP/RTOS/SD do not.

Safe RAM allocation, stack headroom, CPU/SD throughput, storage ownership/USB
exclusion, recovery and the pad-reader exclusion/assignment path remain unproved.
The one-audio-producer contract also remains required. No new chipset conclusion
follows from the Cortex-M7 emulator target or synthetic addresses.

Next concrete investigation
Trace the stock request/admission/stop dispatcher and its worker wakeup mechanism.
Identify whether there is an acknowledgement that all old callbacks have drained
before another take is admitted. Bind a worker schedule and retirement fence only
when supported by original code evidence; otherwise retain explicit cancellation
and single-session limitations. Pad assignment follows that ownership work.
