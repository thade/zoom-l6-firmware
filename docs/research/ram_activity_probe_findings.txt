Passive upper-gap activity diagnostic — 10 October 2026
=====================================================

Purpose and boundary
--------------------
Diagnostic 13 looks for CPU-visible changes in the apparent upper RAM gap. It
does not reserve the gap, write patterns, test aliases, alter cache/MPU/controller
settings or enable extra capture. The preferred feature remains an additional
pre-compressor stereo recording, preserving ordinary MASTER and clean stems.
If ownership is established, contiguous upper-gap storage could avoid shortening
the ordinary native rings. This observer cannot establish that ownership.

Bounded protocol
----------------
Fixed interval [81f26000,82000000): 892928 bytes, 872 pages of 1024 bytes.
Request: F0 52 00 00 6F 02 token page_low7 page_high7 F7 (10 bytes).
Only a fixed page number is accepted, never a host-provided address. The original
Editor state must be 2 and execution must be in Thread context (IPSR=0).
Invalid pages or packet/context fields cause no candidate/controller access.
Other supported diagnostic packets delegate to the prior dispatcher.

Before any gap access require MCR&3 == 0, BR0&fffff03f == 8000001b, and
SDRAMCR3&1 != 0. These match the already observed active 32-MiB CS0 decode with
refresh; they do not detect the fitted memory chip's physical density. Denied
configurations return a reply without gap reads. Read the three configuration
words again afterward and retain both tick readings from 801f9050.

Each accepted page has two sequential passes of 256 volatile uint32 reads.
Each pass computes h=2166136261, s=0, then h=(h XOR word)*16777619 and s+=word,
both modulo 2^32. This is FNV-1a over little-endian words, not bytewise FNV.
The reply is 103 bytes: F0 52 00 00 6E 02 token, 19 uint32 values encoded as
five seven-bit bytes apiece, F7. Values are schema=1, range_id=1, page, count,
page_bytes, address, flags, hash0, sum0, hash1, sum1, ticks0, ticks1, MCR0, BR0,
refresh0, MCR1, BR1, refresh1.
Flags: 1 read performed; 2 paired digests agree; 4 configuration words agree;
8 both configurations accepted. All four are required for a consistent page.
No retry, cache maintenance or register write is performed on disagreement.
