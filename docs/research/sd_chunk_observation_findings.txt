Passive SD chunk-completion observation — 9 October 2026
======================================================

Purpose
-------
Observe actual controller mode and activity at the lowest native DMA data-wait
returns, before bounce-buffer copy/reuse or the next direct chunk. This is a
specific remaining completion question from the Astra composition review.
Clean outer file returns and broad tail guards cannot answer it.

Four byte-checked BL sites call an integer-only observer around the unchanged
native wait at 0x800328c0:
  0x8006a06a: direct read
  0x8006a1f4: bounce read, before the copy at 0x8006a20e
  0x8006ac6e: direct write
  0x8006ae10: bounce write, before next reuse at 0x8006ada8
The original per-unit ownership remains in stock code. All five arguments,
including the stack timeout, returned status and output flags are preserved.
The observer never supplies completion permission, retains a failed frame,
resubmits I/O, resets hardware or changes the file/card state.

Observations and interpretation
------------------------------
Each sample records caller return site, event/task identity, timeout, native
status and successful wait flags; PRES_STATE before and after; SYS_CTRL,
PROT_CTRL, MIX_CTRL, VEND_SPEC2 and sampled DS_ADDR after the wait.
Sequential reads are not an atomic hardware snapshot. DS_ADDR may already have
advanced and must not be labeled the originally submitted address.

A first-anomaly sample remains until reboot; the latest sample and cumulative
wait/site/anomaly/omission counters are also returned. Anomalies include returned
errors, mixed/missing completion flags, sampled activity/reset and unexpected
DMA/endian/argument mode. These are candidate-family interpretation checks, not
hardware-completion proofs or silicon identification. A busy epoch, missed
observer claim, counter reset/wrap or missing reply invalidates complete interval
coverage. A quiet sample does not prove cache visibility or card persistence.

Fixed read-only queries are 73/72 kind 1 latest / kind 2 first anomaly. The legacy
health queries remain available. No general memory/MMIO address endpoint exists.
Queries copy stored observations; they do not read the controller or modify the
trace. Main can query while the native wait is pending; its snapshot is marked
incomplete and the native frame/token remain unchanged in the fixture.

Meaning of the write-side activity (candidate interpretation)
-----------------------------------------------------------
The candidate RT1042 header defines DLSL at bits 24..31; NXP's USDHC API maps
Data0LineLevel to bit 24. Thus the retained write's 0xfe88800e has DATA0 low,
while the retained read's 0xff88800e has DATA0 high. Both have read/write-
transfer-active bits clear. The observed write pattern is consistent with a
trailing card-programming/busy phase after host data transfer.
Primary definitions:
https://raw.githubusercontent.com/nxp-mcuxpresso/mcux-sdk/main/devices/MIMXRT1042/MIMXRT1042.h
https://mcuxpresso.nxp.com/api_doc/dev/816/group__usdhc.html

NXP documents SD_WriteBlocks returning while the card is still busy, with a
separate SD_PollingCardStatusBusy operation for card readiness. Its USDHC data
interrupt handler prioritizes data/DMA errors over completion and optionally
invalidates the received buffer's cache before completion callback. These are
candidate-driver design evidence, not a claim that Zoom uses this exact driver
version or that the installed processor/cache contract has been identified:
https://mcuxpresso.nxp.com/api_doc/dev/3151/a00063.html
https://raw.githubusercontent.com/nxp-mcuxpresso/mcux-sdk/main/drivers/usdhc/fsl_usdhc.c

Therefore do not label every data-inhibit/line-active observation as a DMA
buffer-lifetime failure, nor clear the physical-completion gate from these
successes. Next resolve raw completion/error identity before stock IRQ
acknowledgement, and the exact DMA/cache handoff for candidate buffers. The
existing fixed wait sample cannot recover errors discarded by the native IRQ
mapping or prove stale-event exclusion. Native storage transitions and owned
memory still require binding before enabling the extra recorder. No new broad
guard-only trial is justified solely by this expected-busy candidate pattern.
