Diagnostic protocol and bounds
------------------------------
Fixed SysEx request 75/reply 74 accepts only an eight-byte packet in a connected
Editor session and Thread mode. No address, size, reset, recording or assignment
command is accepted. Legacy timing protocol 7B/7A and stock messages remain.

1: status: guard progress/fault, both arena bases, both descriptor sizes, both
   cached sizes and native cursors. It does not write guards.
2: explicitly initialize at most 512 guard words (2 KiB). Both bases must equal
   the fixed arena, all four sizes must equal 223104, and recording/playback
   cursors must be in range. Native recording/recorded-song activity refuses or
   pauses initialization. All 396 chunks are needed to arm the twelve tails.
   An armed/faulted probe cannot overwrite/rearm guards; reboot starts anew.
3: check the next 512 words, without rewriting guards. One complete sweep is
   396 chunks. First bad address/expected/actual and observed bad words latch;
   faulted scans stop. Counts describe checked chunks, not every corrupted word.
4: requested public READ/WRITE and SD-packet CPU buffer spans: requests,
   overlaps, invalid spans, first intersecting operation/address/length and
   omitted claims. SD byte counts are checked for overflow. No request is
   blocked/retried; the original routine is called exactly once.
5: sample native recorder producer/active consumer positions. Maxima are
   sampled modulo distances; unstable snapshots are skipped. Missed whole laps,
   unsampled maxima and true extra-consumer service/queue delay are invisible.

One weak observer claim precedes each bounded update and is released before
any native IO call or MIDI reply. Busy/missed claims report omissions rather
than waiting for an observer. Individual replies have before/after epochs;
they are not simultaneous cross-page or whole-audio snapshots.

The host tool uses explicit --initialize-guards to write guards. Its bounded
iterator checks each chunk and stops on refused initialization, faults or
incomplete progress. --scan completes one sweep and never writes guards. The
default reads status/source spans and samples backlog, without guard writes.
Fresh logs are required and preserved on failure.
