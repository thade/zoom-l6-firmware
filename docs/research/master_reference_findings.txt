Master reference findings (stock v1.10)
=======================================

Goal: after each ordinary take, pad 1 plays that take's stock master
A:\RECORDER\<take>\MASTER.WAV in place, with no extra recording; sections 7-10
extend it to the four-pad chain, the take history and release 0.1.0.
Sections 1-5 describe the first, pad-1-only design (experiment 24). Static
analysis plus emulation of original instructions; nothing here is hardware
evidence. Implementation: src/capture/master/; checks:
tests/emulation/verify_master_ref.py and verify_master_trial.py.

1. Where the take path lives
Record start (callback 0x80034f40 -> 0x80002df8) formats yymmdd_hhmmss from the
clock (0x800485b0), creates the folder (mkdir 0x8005f3d0; on "exists" it bumps
the time via 0x8000be30 and retries), catalogues and selects it (0x80008848),
then copies "A:\RECORDER\<take>" through 0x8000ae00 -> 0x80004430 ->
0x80022de0 into 0x8060ff80 (UTF-16, at most 0x100 units, NUL forced at
0x8061017e). No trailing backslash. The only other writer chain is
0x80002d30 (boot/SD project load, and a pad-target branch at 0x800035bc);
recorder init 0x80022ce8 zeroes it. Finalize, postprocess and re-arm leave it
alone, so it is valid at and after RecStop until the next record start.
Emulated: naming with a collision bump, the copy into 0x8060ff80, and
0x80022c80(10,1) = "<folder>\MASTER.WAV", (10,2) = "<folder>\MASTER_01.WAV".
Per-stream paths are rebuilt on demand into the shared scratch 0x8060fd80;
the recorder writes "<folder>\Work\MASTER.WAV" (0x80023640) and postprocess
renames it.

2. When the master is final
RecStop 0x8004ba40 calls the stop cursor setter 0x80006918 (LR 0x8004ba4d),
then 0x8000b698: finalize and close streams 0..11, postprocess 0x800032b0 at
0x8000b978 (rename Work\ files to final names, rewrite headers; then remove
Work), re-arm. All of it is synchronous inside the one RecPlayCtl callback,
during which RecPlayCtl's busy word 0x80578ec0 stays 1 (worker 0x80034bc8).
So once 0x80578ec0 reads 0 after a stop observed inside that callback, the
master is closed and renamed. A failed master close still reaches postprocess,
so the file is checked independently (open read-only, size).

3. Splitting
The producer 0x80038e60 splits a stream when its bytes reach the per-stream
threshold (about 2 GiB, set at 0x8060fd80+0x43c by 0x80022ce8). At 48 kHz
stereo: 93.2 min in 32-bit float, 124.3 min in 24-bit, 186.4 min in 16-bit.
Part 2 is MASTER_01.WAV. A split take is refused rather than assigning only
its first part.

4. Assignment and why an anchor is needed
0x80008c68(mode 0, path, pad, index, count, 1) queues the path pointer to
SamplerFileAssign (callback 0x80049d60 -> 0x8004b760). 0x8004b760 validates
the catalogue entry at index (0x80009568) and only the passed path's extension;
it stores the full path at 0x80440dc8+0x798+pad*0x20a (up to 0x104 units) and
loads it (0x800092a0). Settings save and load copy that path raw.
Reload (callback 0x80049da0, boot and File Transfer Mode exit) looks the saved
path's basename up in the pad's folder catalogue. Found: it loads the saved
full path. Not found: it assigns the first valid file in the folder and saves
that, losing the reference (an empty folder keeps the configured path but
loads it only at the UI's load-all). Emulated outcomes after save, cold boot
and reload with the reference A:\RECORDER\...\MASTER.WAV:
  PAD1 = {MASTER.WAV}                 reference kept and loaded
  PAD1 = {BACKING.WAV, MASTER.WAV}    reference kept and loaded
  PAD1 = {BACKING.WAV}                replaced by BACKING.WAV
Hence a permanent anchor A:\SOUND_PAD\PAD1\MASTER.WAV. The validator judges
the anchor's format, not the master's: a 44.1 kHz anchor routes to sample-rate
conversion, so the anchor is 48 kHz. The master itself is parsed by the loader.
The Editor's pad-name query (46 02) for a loaded path whose basename is not
catalogued reads a NULL name (address 0); the anchor avoids that too.

5. Design
Recorder task: admission (0x8000b158) marks an ordinary take; RecStop's
setter call copies 0x8060ff80 (bounded to 63 units, must start A:\RECORDER\)
and appends \MASTER.WAV, then releases a stop counter. Worker (priority 1):
copies the path under that counter, waits for 0x80578ec0 == 0 and no new take,
reads the first 1 KiB of MASTER.WAV (stock layout: fmt at 12, PAD chunk, data
at 902, file ending exactly at the data's end) and requires 48 kHz stereo and
that exact size, checks MASTER_01.WAV is absent, then posts a category-3 Main
event with reposts. The validator answers from the anchor for every take, so
the master's own rate is checked here. A storage change between admission and
RecStop refuses the take; any admission closes a take that ended without the
setter (card cleanup). Main: looks up the anchor (no insert), checks its catalogue path,
validates, stops pad 1 if playing and queues the assignment from a buffer it
keeps until the next assignment, copied only after rechecking the serial,
since the stock calls can block and let the worker supersede it. A newer stop
supersedes an unhandled post; storage changes before assignment skip it.
Emulation runs RecStop through the original RecPlayCtl dispatch: the stock
finalize call happens after the stop is published and with 0x80578ec0 set.

6. Hardware (experiment 24, 12 October 2026)
Confirmed: 32-bit float masters play in place from RECORDER; pad 1 plays the
previous master while the next take records to the same card; the reference
survives a cold reboot and a File Transfer Mode cycle with the anchor present
(saved path read back from L6PADSETTING.ZST); the anchor is catalogued as
MASTER.WAV. Still open then: a deleted folder (resolved in section 9) and
split takes (refused by the check, not exercised on the mixer).

7. Take chain (experiment 25)
All four pads hold the last takes, newest on pad 1. The stock saved pad paths
(0x80440dc8+0x798+pad*0x20a, written by SamplerFileAssign when it loads) are
the only record. After each verified take, Main builds the chain: the new
master, then the take masters saved on the chain pads in pad order, skipping
hand-picked or empty pads and repeats, cut to the chain length; pads past its
end keep their sound and pads already right are skipped. The chain covers
pads 1..n up to the first without an anchor PADn\MASTER.WAV. All formats are
checked before any assignment is queued, oldest pad first (completions save
in order, so an interrupted shift repeats a take rather than losing one).
0x80008c68 (mode 0) sets a per-pad pending byte (0x8044337f+pad, getter
0x800060d0); the assignment callback 0x80049d60 posts Main event {1, 4,
0x1c, pad} after 0x8004b760 on every path, and Main's handler calls
0x80008b00, which clears the byte on success and failure (and may save the
settings via 0x80006b18). A shift waits while any byte is set, so it never
reads a path an earlier assignment has not saved. The assignment queue holds
512 messages of 32 bytes and its sender blocks rather than drops. Emulated
with the original catalogue for all four pads, and with the original save,
cold-boot load and reload keeping all four references. The state moved to one
native-heap allocation published after the worker is created.

8. Take history (experiment 28)
Every pad start reaches 0x80018310 through the play wrapper 0x80002c60, on
Main (pad buttons, MIDI and Editor dispatch); the only write of the renderer
playing flag (0x20015e4c+pad*0x3c, read by 0x80018190) is inside it. A hook
at 0x80018316 (push {r4,lr}; mov r4,r0, after the pad>3 check) records the
pad's saved path while a take is open; pads already playing are seeded from
the flags at admission. Polling cannot work: a 1-frame one-shot is active for
one 64-frame render and the worker can be starved for over a second. The
stock code never lists files inside take folders (the take scan lists
directories only; the stream matcher accepts only its own WAV names), v1.10
has no on-device take delete, and RMDIR removes whole trees (refusing if any
file in the folder is open). HISTORY.TXT is written via HISTORY.TMP (create
0x501/0x80, one write, close, same-folder rename, which refuses an existing
target); writes of 512 bytes or more transfer straight from the buffer, so
it is cleaned first. The filesystem tokens are counting semaphores without
priority inheritance: while the priority-1 worker holds one, the priority-28
file worker can wait, so the write is kept to a few calls.

9. A missing take folder (experiment 29, on the mixer)
Take folders can only disappear over USB, and leaving File Transfer Mode runs
the stock reload: the reload callback finds the anchor's name, the loader then
fails to open the missing master and clears the pad (config NO ASSIGN, pad
unloaded; pressing it is silent). An empty pad is not a take, so the next
chain shift closes up over it and no history can include it. A later reload
gives the empty pad its folder's first valid file, the anchor (emulated).

10. Release 0.1.0 (experiments 26 and 34)
Takes shorter than 96,000 frames (2 s at 48 kHz, from the master header) are
refused as short and stay off the pads; they still get a history. The take
check and every history file call wait while the stock recorder state
0x80578ebc is 1 (recording, ordinary or to a pad) or 2 (playing): stored by
the record start callback 0x8004b9a0 (at 0x8004ba18) and the play start
callback (at 0x8004b8e8), cleared by RecStop (0x8004bae4), PlayStop
(0x8004b966) and the reset 0x80034de8 (at 0x80034e0e). The
ordinary-take flag alone missed pad recordings and playback. HISTORY.TXT
version 2 lists the played pad files first and then each played take's own
history, newest first, at most 100 entries (OMITTED marks the rest);
version 1 files are read too (docs/history-format.md).
