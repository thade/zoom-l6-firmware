L6 PRE-COMPRESSION CAPTURE INVESTIGATION
3 October 2026

Result
Nine offline test groups execute bounded portions of the original pad renderer,
channel/pad mixer, master gain, stereo staging copy, recorder-ring producer and
stream reader. With synthetic samples and state, the candidate pre-master mix
contains live input plus pad playback. A modeled saved-copy substitution reaches
the original stream-10 stereo reader exactly, without modifying the current
monitor mix, input working buffers, or a sentinel in the channel-0 recording ring.

This is evidence for the signal-routing design, not a firmware implementation.
No firmware installed, no flashable image generated, no device communication.

Files
  tests/emulation/verify_uncompressed_tap.py
  analysis/uncompressed_tap_verification.json

Executed signal path
1. Original RAM pad-render/mix window 0x20220ac8..0x20221792 produces pad audio.
   The remainder of that function is not executed; it needs other initialized
   input/ring state. One-pad, two-pad, differing L/R patterns, individual pad
   levels and combined pad level are covered; looping/EOF behavior is not.
2. Original function 0x20224b90 mixes the channel working buffers and pad audio
   into 64-float blocks at 0x20013e00 (L) and 0x20013f00 (R). Input EQ flags and
   gain ramps are disabled in this fixture. Channel 0 has different L/R weights.
   All ten input working buffers remain byte-identical through this operation.
3. Save those 512 bytes in the host test. This models an owned pre-gain snapshot;
   no device hook, memory allocation or real-time synchronization is implemented.
4. Original window 0x202269f8..0x20227136 applies master gain in place. A gain of
   0.5 halves every mixed sample, while the saved snapshot retains original values.
   This boundary precedes the dynamics sections identified in the earlier trace.
5. Original window 0x202280e0..0x202281c6 copies the CURRENT stereo mix to
   0x20012058/0x20012158. Dynamics between steps 4 and 5 are deliberately skipped.
   Consequently this test verifies gain separation, not compressor acoustics.
6. Host test replaces that staging block with the saved snapshot. This is the
   proposed capture substitution, explicitly modeled rather than patched ARM code.
7. Original window 0x2022a55a..0x2022a77a scales and enqueues the master pair.
   The test supplies unity in S18 (this scale's initialization is not yet traced).
   The ring base is 0x81429800, channel stride 0xea600 bytes. Master pair goes to
   offsets 0x927c00 and 0xa12200, exactly channel indices 10 and 11.
8. Original reader 0x80018fd0, supplied stream index 10, two channels and four
   bytes/sample, reads those rings into interleaved stereo bytes. Every sample
   matches the saved snapshot. Both 64-frame positions of a synthetic 128-frame
   ring, including write-position wrap, are tested. Channel-0 mono readback of
   a sentinel is unchanged by master substitution.

Earlier catalogue tests establish that logical recording stream 10 is named
MASTER. These new tests connect the audio-buffer producer to the reader's index
10 and 11 pair. The full recorder task/file writer was not run here, so actual
WAV output and destination remain an integration task rather than a proved result.

What this supports
Preserve the ordinary multitrack recorder. Snapshot its complete stereo mix
before master gain/dynamics, and feed that snapshot to the existing master
recording pair while letting the normal output path continue. This should avoid
reapplying master gain and compression on each accumulated backing pass.

Directly writing that master into a pad directory remains a separate change.
The preferred proposal is a unique new master file in the chosen pad folder,
ordinary channel files in the take folder, and assignment only after successful
finalization. Stock REC+pad mode drops the input tracks; do not simply automate it.
See docs/research/direct_pad_recording_findings.txt.

Pad gain still affects accumulation
The pre-master mix includes individual pad gains and the combined pad level.
The two-pad test verifies this numerically. Capturing before master gain therefore
does not make overdubs independent of pad level. Repeated capture at non-unity
backing gain would still progressively rescale old layers. Input channel levels
and pans similarly determine each new contribution.

Emulator correction
The earlier default emulator could not execute VMAXNM.F32. Selecting Cortex-M7
with M-class mode BEFORE mapping/loading memory, then enabling floating point,
allows that instruction and the tested floating-point mix/gain paths to execute.
This removes that tooling obstacle for the bounded windows; it does not identify
the physical L6 processor or establish full DSP/hardware emulation. The shared
Emulator constructor now accepts optional CPU model/M-class arguments. Defaults
are unchanged. A separate synthetic stack avoids overlapping the audio buffers.
