Passive raw SD IRQ and core-memory observation — 9 October 2026
=============================================================

Result and purpose
------------------
Experiment 10 passes 23 offline groups and is staged/readback verified on the
identified L6 card. The user completed update/reboot, fresh raw replies confirm
execution, and stopped startup/automated playback checkpoints pass. Installed
flash has not been read back. The last detailed ordinary recording showed writes
returning with DAT0 low and data inhibit/line activity, but transfer-active bits
clear. That is consistent with trailing card busy, not a demonstrated unfinished
RAM transfer. This narrow observer captures raw TC/error identity before stock
masking/acknowledgement and core cache/TCM configuration. It supplies observations,
not physical-completion or buffer-reuse permission. Extra capture stays disabled.

Original native boundary
------------------------
At 8006eab6, R0 identifies the native unit and R1 contains the full INT_STATUS
snapshot. The hook replaces six bytes (lsls r4,r1,#0x17; and.w r3,r3,r2) with a
four-byte branch and NOP. The adapter preserves R0..R12/LR and APSR_NZCVQG,
aligns the stack, calls an integer-only observer, restores state, replays the
original instructions, then resumes at 8006eabc before the original W1C.
There are no VFP instructions in compiled probe functions. Differential tests
preserve FPSCR as well as native posts, GPRs, flags and MMIO writes.

Native behavior is unchanged: TC plus a masked data fault can still post
software success flag 4, and CC plus TC can still post only command event 2.
The observer keeps full raw errors separately rather than changing this mapping.
Tests exercise both unit ingress paths. Actual use of unit 1 on this device
remains unknown; both examined callbacks use the same controller body.

Snapshot implementation
-----------------------
A single compare/exchange claims an epoch without waiting. A busy/nested
observation increments the omitted counter and immediately returns to stock.
The observer records interrupt count, unit mask, TC/error counts and independent
first-TC, latest-TC and latest-error samples. Each retained sample contains:
unit, raw INT_STATUS, INT_SIGNAL_EN, PRES_STATE, SYS_CTRL, PROT_CTRL, MIX_CTRL,
DS_ADDR, interrupted task, native unit event handle, CCR, DTCMCR and ITCMCR.
Reads are sequential, not an atomic controller snapshot. DS_ADDR may have
advanced; the task pointer is not labeled a transfer owner. A TC with MIX.DMAEN
counts a sampled DMA-mode TC interrupt, not a proven completed transaction.

Core registers use the architectural layout also present in stock M7 setup:
CCR=e000ed14, DTCMCR=e000ef94 and ITCMCR=e000ef90. They are read only on
TC/error ingress and stored; host queries do not read controller/core registers.
The configuration helps interpret native bounce memory at 2000c4d4. No fitted
RAM capacity, physical DMA reachability or uncached bus claim follows from an
MPU address alone. Exact silicon/revision remains unproved.

Fixed protocol
--------------
Request: F0 52 00 00 75 kind token F7; reply identifier 74.
Kinds 1/2/3 return latest TC / first TC / latest error, schema 1, 21 words,
113 bytes. Kind 4 returns counters and latest stored core settings, schema 2,
14 words, 78 bytes. Each uint32 is five seven-bit bytes. The existing detail
73/72 pages and health 7D/7C remain available through the wrapper dispatcher.
Queries never clear observations, change settings, or grant a join. Odd/changed
epochs are marked incomplete; host validation rejects incorrect kind, token,
schema, lengths, delimiters and uint32 encoding. Zero raw sample means absent.
Every decoded reply explicitly leaves physical_completion_proven and
transfer_owner_identified false. The CLI only emits these four fixed queries.

Hardware cache/TCM interpretation
--------------------------------
First/latest TC agree: CCR=00070200, DTCMCR=00000041, ITCMCR=00000031.
Both caches are enabled. DTCM has EN=1, SZ=8 (128 KiB, 20000000..20020000);
ITCM has EN=1, SZ=6 (32 KiB, 00000000..00008000), with exclusive upper bounds.
Both 4-KiB native bounce areas fit in enabled DTCM.
Arm DDI0489F sections 3.3.6 and 5.8.1/5.8.2 define these encodings and CPU
TCM accesses as uncached regardless of MPU cache attributes. This resolves the
bounce CPU cache path. The architecture's AHBS interface does not prove the
SoC's peripheral interconnect or safe transaction joining. Cached SDRAM history/
staging still need reservation/ownership. These are core-reported sizes, not
new allocations or a silicon part number.

Limits and next bounded step
----------------------------
Hook/state execution, native instruction replay and protocol semantics are
verified with synthetic status/events. Physical interrupt arbitration, bus
access, cache/TCM enforcement, elapsed overhead and stack headroom are not
emulated. All known omissions and busy snapshots make coverage incomplete.
There is no per-command generation arming, prior join, stale drain, source
exclusion or guard on these snapshots. General polling/no-IRQ paths are not
exhausted. Passive success cannot establish failure recovery or authorize the
extra recorder.

Startup/core/read and normal-write observations are now available, including
backing with substantial live input. Further ordinary success trials cannot
establish command generations or buffer ownership by themselves. Bind one
concrete guard beneath payload AND metadata only after prior transfer joining, stale
source exclusion/drain and direct-read cache ownership are established. Outer
storage-transition deferral and exact memory-span qualification still precede
capture-only deployment. Avoid treating normal DAT0 card busy as a reason to
reset the controller.
