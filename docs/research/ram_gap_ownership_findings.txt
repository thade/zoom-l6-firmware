External RAM gap ownership follow-up — 10 October 2026
=====================================================

Result
------
Neither apparent gap is approved for capture. This follow-up found no confirmed
stock consumer inside either interval. It bounded three concrete nearby paths
and resolved the new derived-address scan's two apparent gap constants as
Japanese character-table entries. Negative static findings cannot exclude
runtime pointers, DMA, alternate images or the missing bootloader.

There is now a stronger case for investigating the upper gap first. Its 872 KiB
could hold the current 1024-slot capture history without shortening ordinary
recording/playback buffers. The existing history-storage API already accepts
contiguous slots; a qualified gap would avoid the eight-tail layout. No change
to that layout, native capacity, firmware image or running device was made.

----------------------

The upper start is already 32-byte aligned. A 1024-slot history uses 540,672
bytes, including slot metadata; it holds 65,536 stereo frames / 1.365333 seconds
at 48 kHz. This is a proposed geometry, not a measured sufficient service budget.
Two thousand forty-eight slots need 1,081,344 bytes and do not fit the upper gap.
The separate arena/worker/stack footprint remains approximately 26.5 KB in the
current design and is not included in these remaining-space figures.

If this alternative is qualified, the native rings could retain stock capacity
240000 frames / five seconds rather than 223104 / 4.648 seconds. This would
recover the 352-ms native stall margin removed by the current tail experiment.
It would not remove extra capture's 384,000 B/s storage traffic or resolve its
completion, scheduling, stack, startup and code-size gates. Installed diagnostic
12 retains its prior shortened capacity and keeps extra capture disabled.

Smallest next evidence
----------------------
Prepare a fixed-range passive fingerprint query for bounded pieces of the upper
gap first. Compare complete coverage across idle, ordinary recording, pad/song
playback, effects and before/after card/USB transitions. Query only while the
original Editor/MIDI session is reachable. The query must read only, keep each
handler bounded, preserve the earlier diagnostics and leave capture disabled.
No host-supplied arbitrary address, pattern/canary writes or live reservation.
A changed byte/fingerprint identifies activity and rules out an unconditional
reservation; unchanged readings only add evidence. A range can be used read-only
by native code without changing, and a digest has collision limits. This test
cannot grant ownership or prove physical address independence. Ordinary CPU
reads may see cached bytes and miss DMA writes; do not clean/invalidate unowned
cache lines or change MPU/controller settings to strengthen this observation.

In parallel, continue targeted tracing of callers which provide RAM destinations
to audio/USB/DMA and remaining pools. Neither broad reads nor a harmless startup
trial replaces that work. Before using either gap, document an ownership basis,
physical/cache alias evidence and all required producer/consumer bounds. If
that cannot be established non-invasively, retain the already-tested tail
candidate while qualifying its reduced ordinary margin, or obtain physical
chip/bootloader evidence. Pre-compressor capture remains the preferred feature;
this audit gives no reason to pivot to the master-only fallback.

prepared image passes 53 offline groups, retaining all 42 prior diagnostic
checks. It covers 872 fixed 1-KiB pages, reads each twice, and adds no reservation,
patterns, cache maintenance or controller writes. Card staging/readback and

memory providers, aliases and unexercised transition paths are unresolved. This does not change
any ownership conclusion or the capture layout. Detailed protocol, conservative
