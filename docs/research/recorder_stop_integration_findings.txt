L6 recorder stop integrated with the extra-file manager (offline)
2026-10-04

Result
The original queued stop callback now runs the stock recorder shutdown backend
inside a combined emulator test of the compiled extra-writer, session manager
and pad publisher. The previous deep-stop placeholder is removed in this new
fixture. Seven integration groups pass. No C or assembly change was needed: the
existing request ownership and manager completion gates handle this sequence.
This is a stronger integration test, not a newly installed firmware hook.

What runs together
- Original request and RecPlayCtl dispatch code, through the existing compiled
  request/envelope adapters and original stop callback 0x8004ba40.
- Original backend 0x8000b698, saved-endpoint getter 0x80006168, stream-limit
  calculator 0x800382a8, stop predicates, file handle/length getters, WAV
  finalizers, recorder reset and postprocessing dispatcher 0x800032b0.
- Compiled extra-file capture, checked finalization/close/readback, request
  retirement and session manager, then the existing pad publication adapter.
- All seven ordinary files: logical 0 and 1 mono; 2, 4, 6, 8 and 10 stereo.
  The seventh is the normal processed-master route, not the extra file.

What remains modeled
Ordinary recording admission/handles and audio payloads are fixture inputs.
The public filesystem uses in-memory files. Final ordinary drain scheduling is
explicit: stream-active bits clear, then producer busy clears. The final queued
ordinary write itself is not newly executed in this integration test; that
worker/token ordering has separate earlier evidence. Deep per-file postprocessing
is intercepted, so this is not end-to-end Work-directory relocation/rewrite.
DSP, RTOS scheduling and device memory/cache/DMA remain outside this test.

Integration checks
1. Normal completion: seven original WAV finalizers and closes run before
   postprocessing. The extra file has exactly 128 stereo frames from the
   selected interval, passes readback, reaches the manager RESET boundary and
   is published through the existing pad adapter. Its ordinary counterparts
   retain their seeded audio byte-for-byte with correct updated WAV lengths.
2. Stop cursor wrap: a 256-frame extra take spans the 256-frame synthetic source
   ring. With one final ordinary block modeled outstanding, the original limit
   calculator yields 256 for every enabled stream. The extra WAV contains the
   corresponding exact monotonic sample interval, not an empty modulo range.
3. Controlled slow stop: pause RecPlayCtl at its first drain wait and run the
   compiled manager on an independent emulator CPU with copied prototype RAM.
   The extra file can finish and close, but bridge eligibility and manager
   results remain withheld while the stock callback still owns its request.
   The manager remains FINISH, not yet FENCE; no queue marker is sent. After
   resuming stock stop, all ordinary closes/postprocessing finish, ownership
   is released and the normal completion fence permits the result.
4-7. Inject extra audio short-write, final-header write error, write-close error
   and readback error. Stock stop still finishes all seven ordinary files. No
   new manager result is exposed and publication is refused. An existing
   BACKING.WAV, registered and selected with the stock catalogue/assignment
   routines, retains its assignment, bytes and saved pad settings. Write-close
   uncertainty leaves the manager BLOCKED; the other cases end STOPPED.

The independent-CPU experiment transfers only the prototype globals/session
arena and optional-file effects back while the original callback is paused.
It does not execute two real RTOS tasks concurrently or explore every schedule.
The pad publisher uses an explicit modeled playback-exclusion contract. Its
successful assignment does not prove native pad-reader exclusion or reload.

Why this matters
The extra recorder does not need a bespoke card-wide shutdown for each take.
It can share the ordinary stop sample and file layer, while retaining its own
checked file lifecycle. The completion gate already prevents an early-finished
extra file from becoming eligible while the ordinary stop callback is pending.
The native scheduling/binding work should preserve that ownership sequence.

This test covers extra-file failures, not a new policy for ordinary-stem errors.
The earlier stock-only audit still applies: the stock routine may continue after
an ordinary header/close error. No claim is made that all ordinary-error recovery
or every file-access ingress is now integrated.

Next bounded step
Replace the modeled ordinary drain in this combined fixture with the original
stream producer/file-access-worker completion route, retaining a delayed last
write and the same request lifetime. This is the remaining gap between the
stock stop polling tested here and its previously tested write-token mechanism.
Native task registration, spare RAM/CPU budget, physical SD tests and recovery
remain prerequisites for deployment; none are supplied by this integration.
