Why the actual token wrappers
Filesystem selector 8001bf88 ignores the normalized take result and returns
zero. Observing its return would falsely report acquisition on native failure.
The original 800328f0 wrapper supplies timeout -1 and reaches 800327c8; the
kernel 80076950 return 1 becomes normalized success 0, other returns -50.
The give wrapper tail-branches to 80032588; kernel 800763d8 return 1 becomes 0,
other returns -43. Instrumenting these boundaries preserves native behaviour
and observes normalized results rather than claiming ownership from a selector.

Publication and correlation
Eight permanent zero-loaded slots hold one stable current TCB each, from
W(808e291c), admitted only in Thread mode with scheduler flag W(801f9048)==1.
A single weak compare-exchange attempts a free slot; a miss is counted without
retrying admission. Full slots/context skips also retain the original operation.
Per-task fields are atomic; an epoch begins before writes and ends before EVERY
native call that can block/schedule. Thus WAIT, HELD and HELD|GIVING snapshots
can be consistent while the native operation remains in progress. Stable slot
ownership and one writer exclude task deletion/reuse and IRQ writers.

Each public job records operation (READ=1/WRITE=2), handle, requested bytes,
entry tick and per-task sequence. Nested token takes copy that parent context.
The public slot cannot replace an active outer job: nested calls are counted
and passed through. Token users outside READ/WRITE report parent job/identity/
amount zero. The native close fixture produces the largest domain held interval
without a public job, illustrating why zero must not be called an extra writer.

Context state combines B(80578ebc) with B(801f8c50)<<8. Token held peaks retain
the state at take entry; public peaks sample state and tick at completion.
Do not equate these bytes with exact recording boundary or complete physical
button ingress. Durations/counters are uint32 modulo; jobs wrap, and unchanged
maxima do not identify each later equally long event.

Timing meaning
Take duration: wrapper entry to normalized native take return, including wait
and any scheduling before the return. HELD body: successful take return to give
entry, including scheduling within that interval. Give duration: give entry to
normalized return, including any post-release scheduling. HELD is a lower bound
on true ownership, not the exact acquisition/release interval. SD held body does
not isolate card busy, DMA completion or preemption. Probe overhead contributes
to measured intervals. There is no new consumer, enqueue/ack trace or measured
consumer admission-to-progress gap; maxima cannot choose the production buffer.

Protocol
Fixed 77 requests / 76 replies, kinds 1..41 and 7-bit token, require connected
Editor state 2 and Thread mode. Kind 1: schema/layout, five original heap words,
six global omission counters and tick. 2..9: task file pages. 10..41: task/token
pages in filesystem1/filesystem2/SD1/SD2 order. Each task page gives owner,
epoch-before, fixed fields, epoch-after and tick. Equality/evenness validates
only that page. There is no multi-page coherence or arbitrary memory/reset API.
The maximum reply is 153 bytes, copied by the original protected Editor sender.
Legacy 7B/7A timing is retained; no 79 reservation handler is linked.

Implication and next boundary
At approximately one millisecond per native tick, a 481-ms continuing producer
makes 184,704 float stereo sample bytes. That exceeds the entire 163,104 free
heap before history metadata, staging, stack or reserve. A new same-domain
writer arriving near the beginning can be blocked longer than today's
170.667-ms history. This now has observed held-body support; the old aggregate
460-ms call alone did not distinguish pre-acquisition waiting. It still does
not measure optional-consumer admission-to-progress, maximum future latency,
occupancy, catch-up, exact physical busy or DMA/cache completion. The 962-tick
take is a separate scheduling/wait observation and is not a buffer budget.

Next, audit the original serialized writer's producer/staging ownership and
completion ordering offline before inserting any extra job. In the same design
work, establish an explicitly owned larger history layout; merely eliminating
the extra worker or enlarging the heap arena cannot hold this sample backlog.
A subsequent diagnostic should cover the relevant native task set and recognize
saturation before recording, preserving stable TCB identity rather than silently
recycling live slots. No new measurement image or capture deployment is prepared
by this workload analysis. Physical completion, storage transitions, startup
release and eventual pad handoff remain separate gates.
