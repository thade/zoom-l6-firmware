Combined capture, Main retirement and retained SD guards — 10 October 2026
========================================================================

Result
------
One offline ELF now contains the minimal segmented capture, heap arena, worker,
generation lease, Main receive binding, and the existing SD admission/chunk/
event/cache helpers. It uses the same guard sources under L6_SD_RETAIN_ONLY.
That variant excludes the test recovery and synthetic IRQ-delivery callbacks,
stop/reset/retry code and enclosing operation-finish model. A fault instead
yields indefinitely while retaining the original transfer frames, unit token
and buffers. Existing research behavior remains in its separate test profile.

This is an integration and size milestone, not a deployable capture image.
The initial source contract is still unbound: its new pointer defaults to zero.
Admission and completion pointers also start zero, and missing permissions hold
before native bounce-buffer effects or DS_ADDR. Applying the SD patches in that
state would hold ordinary native file IO as well; the combined ELF is therefore
NOT a passive diagnostic or a complete bootable candidate. No BIN is generated.

Verification
------------
The original nine focused groups cover this linked ELF:
- Original scatter executes the LZ4 helper, initializes all eight original
  regions and the combined code/globals, and stops before Main on corrupt size.
- Compiled native cold registration allocates the same arena and starts a worker
  that only sleeps, with all SD permission pointers and capture hooks inactive.
- After explicit model release, capture preserves seven ordinary files and
  finishes its exact extra TMP; the file backend is logical in this case.
- Main retains a USB request and later FIFO packet while a capture write is
  pending, and continues only after modeled storage closure.
- Twenty-four native direct/bounce read/write cases across two stack alignments
  preserve payloads and commands with exact in-range SD patches and native drain.
- Missing source/admission/completion permissions stop before buffer/address effects.
- Split transfers resume after modeled source admission; command/data errors and
  timeout retain original frames through repeated scheduler opportunities,
  without recovery callbacks, follow-up commands or later buffer reuse.
- A lying source model still admits a late prior-origin TC. This negative control
  explicitly prevents treating the combined link as physical source proof.

IRQ timing now comes from the host test scheduler, not a callback inside the
compiled retained guard. Original IRQ/event instructions execute. Exception
arbitration, DMA/W1C/cache effects and positive source permission remain models.
The startup, capture/Main and native-SD checks exercise the same linked artifact
in separate bounded harnesses; they are NOT one concurrent whole-board boot or
eight-stream physical-card simulation.
