CAPTURE CODE PLACEMENT AND ABSOLUTE AUDIO JUMPS — 5 OCTOBER 2026

An offline capture-only ELF now links at candidate device addresses. Two audio
sites execute actual jump bytes with complete instruction replay, without PC
interception there. The original application startup copier carries the bytes
into RAM. Relocated capture produces an exact pre-gain TMP and seven unchanged
ordinary recordings. No installable image, device loading proof or device access
is provided. Hardware testing remains deferred.

Placement and loader boundary

Initialized code: [0x800b6b00,0x800bc424), 22,820 bytes.
Rounded candidate budget: [0x800b6b00,0x800bc440).
Permanent globals: [0x80960080,0x809600dc), 92 zero-fill bytes.

Explicit ELF program headers prevent loading the ELF header over earlier stock
code. Text/constants share an executable segment; globals have a writable one.
The linker bounds code before 0x801f5400 and globals within the proposed 96-byte
arena. Data initializers have a separate load address; currently there are none.

Stock MAIN's effective payload ends at 0x800b6ae4. Candidate reserved file bytes
are all ff, but the vendor bootloader is absent from the update file. Acceptance
of extended MAIN length is unknown. The emulator loads the ELF directly. Making
its code inaccessible causes the actual RAM jump to fail on target fetch. RAM
patch delivery alone cannot prove that the device loads the added code.

Inline jumps avoid nearby veneers

A four-byte Thumb B.W cannot span from 0x2022xxxx to 0x800bxxxx. Both sites have
complete instruction spans large enough for LDR.W PC and an aligned destination
literal. The jump itself needs no code cave, scratch register, stack slot or LR
change. Its adapter saves integer/FPU registers and APSR/FPSCR, aligns the C-call
stack, calls bridge_hook, restores state and replays the entire original span.

  encoding: LDR.W PC,[PC,#0], four-byte Thumb target literal

The IT block ends before commit; tests exercise both conditional MOV paths and
the original DSP prologue at 0x202263e0. Linear disassembly of the copied RAM
block found no direct branch into either displaced span. It cannot rule out other
origins, indirect entries, code/data ambiguity or alternate callback coverage.

RAM and startup requirements

Globals need zeroing before any optional hook entry; here they start zero in
synthetic memory. No device initializer is installed. Manager/worker must also
be initialized before registration. Other arenas retain synthetic test addresses;
their proposed physical ranges remain arithmetic without ownership approval.

The shared save frame costs 192 bytes plus up to four bytes of dynamic alignment
before the C call. The stock DSP frame is 392 bytes. These are partial stack
costs, not peak call-chain/interrupt measurements. Proposed worker allocation is
16 KiB plus a stock 148-byte task object and allocator overhead. Priority/polling
budgets remain experimental.
