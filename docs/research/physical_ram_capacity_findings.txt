Physical RAM capacity and fixed configuration query — 10 October 2026
====================================================================

Conclusion
----------
Live hardware now confirms one enabled 32-MiB SDRAM decode window, with a 16-bit
bus, nine column bits, four banks and refresh enabled. All three queries and
their paired register snapshots agree. This strengthens the 32-MiB physical
capacity hypothesis, but does not detect the fitted chip's density or prove
unused RAM. The application also configures a 32-MiB MPU region and places ordinary
storage through exclusive address 81f26000, 32,661,504 bytes (31.1484375 MiB)
above 80000000. That is software intent plus evidence of working ordinary
recording, not a controlled physical address-independence test. Larger fitted
chips can be partially mapped, and configured windows can exceed physical RAM.

The leading binary matches, RT1041/RT1042, have 512 KiB of internal FlexRAM,
shared between ITCM, DTCM and OCRAM. RT1043/RT1046 have an additional 512 KiB
OCRAM; the exact derivative remains unconfirmed. NXP's current family page says
"up to" 1 MB, so use the individual ordering table rather than assign that total
to the L6. The large recording buffers necessarily require external memory under
this candidate-family interpretation.

Independent precedent, not L6 chip identification: NXP's RT1040 evaluation board
uses Winbond W9825G6KH, a 256-Mbit (32-MiB), 16-bit SDRAM. Winbond confirms its
density/interface. No readable L6 RAM marking or service schematic was recovered
in the public searches. There is no basis to claim Zoom uses this particular RAM.

Existing hardware evidence independently reports DTCMCR=41 (128 KiB enabled)
and ITCMCR=31 (32 KiB enabled), from diagnostic 10. Those describe the active
core TCM mappings, not total internal RAM or spare capacity; see
sd_raw_observation_findings.txt. GPR16/17 and the new query can add configuration
evidence, but GPR17 is selected only when GPR16 bit2 is set. Neither a CPUID nor
the shared candidate DIGPROG value identifies an exact RT104x part.

The package boot descriptor length is zero; the installed bootloader is absent.
The application's reset entry and scatter run in external RAM, so usable memory
must already exist before those instructions execute. Controller initialization
probably predates this application, but its location is not recovered here.

The scan expands every initialized scatter region, scans raw byte-aligned words
for SEMC register addresses 402f0000..402f013f, and attempts a Thumb decode at
each halfword with bounded same-register MOVW/MOVT pairs within 32 subsequent
bytes. It visits 806,664 candidate starts and 8,211 MOVW candidates. Eighteen
raw words fall in the range, all at unaligned offsets; no bounded MOVW/MOVT pair
does. None is treated as a recovered controller configuration. Alignment alone
does not disqualify an indirect pointer. Other constructions, pointer arithmetic,
mixed code/data, aliases and the missing bootloader remain outside this scan.

The original apparent scatter gap remains 2,462,600 bytes at
[80960078,80bb9400). If external RAM is 32 MiB, another 892,928 bytes lie between
the last scatter destination and 82000000. Neither gap is reserved or approved
for use. Physical capacity and complete ownership must precede moving capture
history there. This investigation does not select or change the history layout.

How far that gets us
--------------------
A consistent 32-MiB enabled SDRAM window, compatible width/geometry and existing
ordinary recording provide stronger non-invasive evidence for usable mapped
capacity. They still cannot distinguish a 32-MiB chip from a larger chip mapped
as 32 MiB, identify a manufacturer, prove arbitrary high addresses distinct, or
make an apparent gap safe to reserve. Definitive fitted density needs a readable
part/BOM or a controlled address-independence test with independently owned,
quiescent locations and correct cache handling. Do not write patterns into
unowned running memory or treat identical reads as an alias proof.

Next after the read is an ownership census of the two apparent gaps and remaining
internal RAM. If suitable owned memory exists, keep the ordinary five-second
buffers. No conclusion yet establishes that their shortening is necessary.

The first derived-address ownership follow-up now passes 32 focused offline
groups and bounds three concrete nearby consumers. Its two new gap constants
are verified character-table entries, not recovered live pointers. Neither
gap is reserved. See ram_gap_ownership_findings.txt for exact scope, capacity
arithmetic and the proposed passive activity check; no device change was made.
