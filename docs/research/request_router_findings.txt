Request ownership
Each fresh zeroed Request owns its immutable router/session identity, a unique
per-router request number, its selected stock cursor and resolved absolute sample
timestamp. The router is 20 bytes, Request 64 bytes, and extended Bridge 240 bytes.
These are emulator layouts, not approved device memory allocations.

At begin, a request reserves a Bridge actor. The reservation lasts through both
the queue-send outcome and callback completion. This prevents final eligibility
or retirement while a prior owned request can still deliver an event. A callback
may complete before the sender resumes: its reservation stays held until the
send result is known. Caller storage remains alive throughout, and no Request
object may be reused. Real reclamation still requires the external fence against
stale untagged stock callbacks; rr_released alone does not supply that fence.

Original request setter 0x80006908 now only snapshots into the explicit request
scope when routed mode is enabled. It does not emit START. The actual accepted
start branch at 0x80035030 publishes that owned timestamp before entering the
stock producer. Stop producer entry 0x8004b718 associates a separate request
with the existing take. Rejection/ignore return discards only its own provisional
request. The same raw reject hook no longer cancels a different active take.

The first accepted start owns the optional take for the lifetime of the router.
Another accepted start is unsupported: it cancels optional capture (error 24),
retains the original owner, and still tracks the new queued request through its
send/delivery lifetime. It does not attempt to undo ordinary firmware actions.
A busy or otherwise ignored request does not reach that accepted-start branch.

New instruction adapters
0x80035030: accepted start; resume original tail branch to 0x8004b6d8.
0x8004b718: stop submission; replay push {r4,lr}, resume 0x8004b71a.
0x8004b708: observe start queue result, replay ldr r0,[r4], resume 0x8004b70a.
0x8004b74a: observe stop queue result, replay ldr r0,[r4], resume 0x8004b74c.
They use the existing register/FPU/status-preserving trampoline macro. Their
request branches execute in tests; the existing full register-state comparison
continues to exercise the shared macro at the audio tap.

Queue result and callback attribution
The sender-result adapters observe 0x800483f8's return before mutex release
overwrites it. Zero means queued in the tested contract. Nonzero cancels optional
eligibility but retains the request as uncertain (error 22): wrapper failure
alone has not established a safe non-delivery/reclamation contract. The explicit
rr_sent API can later accept confirmed non-delivery, or a definitive queued
outcome and callback completion. There is no automatic timeout/release. A claim
of non-delivery after actual dispatch is contradictory and faults capture (23).

rr_dispatch requires the exact router, session, owned request and an unused
delivery state. Completed replays and wrong-session/router objects are rejected
without mutating the current bridge. Admission at 0x8000b158 and stop cursor at
0x80006918 apply only through the explicitly scoped callback's owned request.
Admission validates the ordinary handle/mask topology as before. Returning from
an attributed callback without its required checkpoint cancels the optional file.

Stock saved-cursor consistency
The ordinary recorder still uses the global saved start. A subsequent ignored
request can overwrite it while an earlier accepted start is waiting in the
queue. The router checks that saved cursor against the accepted request before
admission; a mismatch cancels optional capture (25), preventing a knowingly
different extra-file start. It does not restore/redirect ordinary saved state.
This is a conservative cancellation, not complete concurrent-request support.
Modulo equality also does not establish stock-ring retention across full laps;
full ordinary/extra timeline integration under long setup delays remains unproved.

Verified cases
- Original start and Record-to-stop request branches yield exact [64,576) audio.
- Busy, playback-state and rejected requests do not cancel an admitted take.
- Request-owned absolute timestamp survives multiple synthetic stock ring wraps.
- Callback-before-send-result ordering retains ownership correctly.
- Send failure retains uncertain ownership until fixture-confirmed non-delivery.
- Completed replays and wrong-session callbacks cannot publish control events.
- Missing admission checkpoint cancels and closes the optional file.
- Unknown outcome blocks retirement; contradictory outcomes invalidate success.
- Overlapping accepted start cancels but retains its queued callback reservation.
- Scope overlap and request-object reuse are rejected.
- Changed ordinary saved start before admission cancels the optional file.

What is still modeled
All router operations are externally serialized in this version. Request and
callback scopes are explicit Bridge pointers, NOT real task-local storage. The
emulator ensures no unrelated task executes a control hook within another task's
scope. This cannot simply be installed as a pair of globals on a concurrent RTOS.
The request pointer accompanying each queue job is an emulator sidecar; the
stock 32-byte message format is not modified. Its identity remains live until
the fixture supplies actual send/delivery completion.

The full high-level request executes, but callback bodies use original admission
and stop checkpoints with registration/file setup supplied by fixtures. Full
RTOS, SD, callback bodies and arbitrary instruction preemption do not execute.
No hardware memory/cache/timing/recovery or pad-assignment guarantee follows.
