L6 WHOLE AUDIO-CALLBACK OWNERSHIP
4 October 2026

Result
An opt-in emulator adapter now holds one Bridge gateway reservation and, when
admitted, one session actor reservation across the selected audio callback.
Its tap and commit hooks use that pinned Bridge rather than loading whichever
session is current later. Detachment waits at pauses between the individual
hooks. Bare taps/commits outside an admitted invocation cannot join a session.

This addresses the inter-hook lifetime gap identified by the previous negative
control. Restart remains disabled: no atomic gate reopening, fresh-file manager
or result/pad handoff is added. Historical isolated-hook fixtures retain legacy
mode and the earlier negative control still reproduces that legacy defect.

Verification: all 157 groups pass (147 preceding plus 10 new). Historical
negative controls remain included and do not demonstrate device readiness.

1. Stock boundary inspected
0x80010776 compares the audio input positions; the mismatch branch at 0x80010778
bypasses this callback-dispatch region. In the dispatch path:
  0x80010788 loads the selected callback pointer into r0.
  0x8001078a CBZ r0,0x8001078e skips a null callback.
  0x8001078c BLX r0 invokes the selected callback, return address 0x8001078f.
  0x8001078e BL 0x80010150 is the common continuation after return/null skip.
  0x80010792 resumes the following output-processing setup.
The boundary covers this selected callback, not the complete outer audio/IRQ
routine or every DSP entry anywhere in the firmware.

emulator_audio_outer_hook replaces the legacy outer observation at 0x8001078a,
reserves the invocation, restores live state and replays CBZ. The original BLX
at 0x8001078c executes on the non-null path. emulator_audio_return_hook intercepts
0x8001078e, releases invocation ownership and replays the displaced BL semantics
by setting LR=0x80010793 and branching to 0x80010150. It does not recurse through
the intercepted site. The null path reaches exactly the same cleanup hook.

Both adapters reuse the existing save/restore of r0-r12, LR, s0-s31, APSR and
FPSCR, with stack alignment for their inserted C call. Differential tests compare
entry and post-return continuation state against the stock windows. They do not
prove exception/lazy-FPU handling or stack headroom on physical hardware.

2. Permanent invocation state
bridge_audio_enable selects strict mode during externally quiescent setup.
The new pair of adapters is required when using that mode; it must not be mixed
with the legacy outer-only hook. No disable/reopen API is supplied.

The outer adapter increments permanent bridge_audio_calls before obtaining the
Bridge gateway reservation or reading the session pointer. It then acquires the
session actor, pins Bridge, checks the actual selected callback and validates the
existing stream observation. The callback body runs normally, without holding
an RTOS critical section. No audio hook performs file IO.

Strict taps/commits require exactly one active invocation, a pinned Bridge and
no overlap fault. Tap must occur once before commit. The pinned pointer is used
throughout; a tap cannot attach itself by consulting emulator_bridge_current.
The return hook checks for missing completion, releases the actor and finally
releases the gateway after its last Bridge access. The permanent invocation
count is decremented during return cleanup; the gateway remains held through
all remaining session accesses. Binding also rejects a nonzero invocation count.

A completed/closed session may reject the session actor, but the outer call still
holds its gateway reservation until return. This matters when ordinary audio
continues after file completion: shutdown still accounts for that callback's
entire interval. After gateway closure, ordinary callback execution continues
with no session access. New closed-gateway calls are still represented by the
permanent invocation counter, which a future reopening protocol must consider.

Single audio producer and balanced outer/return hooks are explicit contracts.
Nested calls set overlap; their taps are suppressed and optional capture is
cancelled (31) when the outer ownership drains. Missing/repeated/out-of-order tap
or commit cancels (32). Null or alternate callback cancels (18) and still returns
through cleanup. A callback that never returns retains ownership and blocks
completion/detach; no timeout forcibly releases live state. Arbitrary concurrent
producer entry/exit on multiple CPUs is unsupported, not made safe by this depth
counter. Real interrupt/preemption and callback coverage still need validation.

3. Verification scope
The test executes original dispatch/continuation windows and compiled adapters.
The callback body is explicitly synthetic: it invokes tap/commit, advances the
stock-cursor fixture and exposes three pause points. It does not execute the
complete original DSP callback. Original gain, staging and ring windows continue
to be exercised by preceding suites, which are rerun on the same build.

Ten new groups cover:
1. Six callback invocations, exact [0,384) stereo extra WAV, balanced counters.
2. Detach at pauses before tap, between tap/commit and just before return; the
   gateway remains owned until return. Each pause uses an independent peer CPU.
3. Missing tap, missing commit and duplicate tap cancel optional capture and
   return all invocation ownership.
4. Null and alternate callback paths retain original branching/return behavior
   and do not leak reservations.
5. Nested callback suppresses taps, cancels optional capture and drains ownership.
6. Suspended outer invocation prevents final file eligibility and detach. Worker
   executes on a peer CPU with explicit shared-memory and file-fixture transfer.
7. Bare strict-mode tap/commit leaves Exchange unchanged, followed by a valid
   callback that produces the exact expected WAV.
8. After detachment, protect all session/sample memory and run normal, null and
   alternate callback dispatch. None touches the protected pages.
9. Strict adapter with owned automatic requests, queued callbacks, control drain,
   exact [64,256) WAV and complete Transport shutdown; later audio still executes
   with all old session memory protected.
10. Differential live register/FPU/status/stack and return-continuation checks for
    the new entry and return adapters.

Peer CPUs transfer shared protocol bytes at selected pauses; this is controlled
interleaving, not full RTOS scheduling. Filesystem calls remain synchronous mocks.
The synthetic callback source is test infrastructure, not a proposed replacement
for Zoom's DSP. No firmware image is patched or exported for installation.

4. Next boundary
Design atomic handover to a prepared fresh session at a known callback boundary.
It must account for callbacks that begin while gateways are closed, the last
return hook's cleanup, control wrappers/callback generation, stable result-path
ownership, and failure of fresh-file preparation. A simple counter reset is
still not an acceptable reopening operation. Test repeated takes and all old
entry/callback interleavings before exposing a restart API.

Hardware RAM/cache/atomic behavior, stack/timing, real SD/DMA buffer lifetime,
close-error recovery, pad assignment and bootloader recovery remain unresolved.
No connected device or card data was changed.

Follow-up: analysis/session_handover_findings.txt now implements prepared-file
adoption at a strict callback boundary followed by control activation. Five
successive same-arena recordings are verified. Raw reset/rebind remains unsafe;
complete automatic manager scheduling and pad assignment are still pending.
