1. Readback now uses stock state rather than the harness's pad list
Main settings structure: 0x80440dc8.
0x80006200(pad) returns path at base+0x798+pad*0x20a.
0x800061f0(pad) returns assigned/enabled byte at base+0xfc0+pad.
0x80006238(pad) returns mode byte at base+0xfc4+pad.
0x80006218(pad) returns native level byte at base+0xfc8+pad.
0x80006228(pad) returns another per-pad byte at base+0x329+pad; this adapter
preserves it without relying on a newly inferred user-facing interpretation.

Sampler state: 0x807348d0 + pad*0x22c.
0x800362b8 returns loaded state at +0.
0x80036318 returns retained sample file handle at +4.
0x800363f0 sets its inline UTF-16 path at +0x20.
Snapshot requires configured and runtime paths to agree, enabled/loaded states
to equal one, and a nonzero retained handle. Empty/NO ASSIGN is normalized to an
empty prototype path only when both flags are clear. Bad/inconsistent state is
rejected. This validates software state, not actual audible sample playback.

2. Assignment is not reliably described by its return value
0x8004b760(path,pad,index,count,option) calls format validator 0x80009568.
Unsupported input returns -1 before assignment. Compatible input stops/unloads
the old sample, writes its path through 0x800069a8, and invokes 0x800092a0.
The latter opens/parses/configures the sample, or clears state/path on failure.
However, 0x8004b760 subsequently returns zero even after a late loader failure.
The new test reproduces that false success using original control instructions.

Adapter first resolves the basename in the specified pad catalogue and confirms
the resulting full path equals the requested path. This prevents accidentally
selecting a same-basename file from another directory. It calls 0x8004b760 and
then performs the strict readback above, including preservation of option bytes.
0x80008bd0 is intentionally bypassed: its return is an unlock result and it may
save settings per assignment. No low-level audio request is sent to real hardware.

The integrated emulator runs actual 0x80009568 and 0x800092a0 branches, stock
path/parameter/state setters and getters, and stock unload 0x800096f8. It models
the RIFF parser's format/length outputs at 0x8000f0b0, position reporting, audio
engine/prefetch calls, RTOS primitives, and filesystem drivers. The independently
tested core validates the WAV before this loader path. Original physical RIFF
parsing and actual audio prefetch remain unverified in this integrated harness.

Restore reassigns a previous path using the same checked path, or unloads and
sets NO ASSIGN for an originally empty pad. Loaded samples legitimately retain
open handles; tests distinguish those from leaked copy/verification handles.
If an option changed unexpectedly, restore fails instead of guessing how to
repair unidentified audio runtime state. The core then latches its fault state.

3. Settings persistence needs stronger checks than the stock convenience saver
Pad settings are stored in A:\SOUND_PAD\L6PADSETTING.ZST.
File layout: 0x60-byte header from runtime 0x800a202e, then 0x1034 bytes from
cached pad settings at 0x80445524. Total size 0x1094 (4,244 bytes).

0x80006b18 compares 0xc34 bytes of live settings beginning at 0x80441560 with
the cached block. If changed, 0x80034318 copies live settings into the cache,
then 0x80034330 -> 0x8004b598 writes the file. The cache changes BEFORE the
write. A failed write followed by an unchanged retry can therefore skip disk
output and return zero. The integrated test reproduces this behaviour.

0x8004b598 checks write status but ignores actual transferred counts and the
close return. Tests reproduce zero return after a short body write and after a
close error. Its non-special write-error branches can also attempt file deletion;
those deletion branches are static observations, not used by our adapter.

The new adapter uses stock cache-copy and filesystem wrappers directly. Each
attempt writes header/body, checks both status and counts, checks close, reopens,
checks exact size, and compares every byte against header/cache. It forces output
on retry rather than taking the cached-equality shortcut. It creates a missing
file only for the observed not-found status; other open errors are propagated.
It preserves the uninterpreted 0x400-byte cache tail; the test seeds nonzero data
there and confirms it survives all six promotions.

This is an in-place write, not an atomic replacement or a power-loss transaction.
The core attempts to restore the prior pad selection and save it again after an
error. Tested write/short-write/close failures recover the meaningful old settings
and leave the session history unchanged. Stock string setters leave unused bytes
after the UTF-16 terminator; rollback tests ignore only that padding and compare
every other settings-file byte. Byte-identical restoration of unused padding is
not claimed. Physical media durability and a failure during rollback remain risks.

4. Scheduler exclusion remains unresolved; do not substitute a busy boolean
0x800075a8 -> 0x80027498 locks the mutex referenced at 0x804468cc, writes the
boolean word at 0x801f8ed8, then unlocks. It does not hold that mutex across the
assignment operation. 0x8004b760 sets this boolean to one and later zero.
The integrated test sets it to one before promotion and observes it cleared by
the inner stock assignment. This is not a nestable outer-operation guard.

The RecPlayCtl worker 0x80034bc8 independently marks 0x80578ec0 busy while
executing its callback, then clears it. This serializes that worker's callbacks
but has not been shown to exclude sampler work, file-transfer transitions or
catalogue scans. Enter/leave/checkpoint and finalized-recording qualification
remain harness models. A real implementation must identify and gate every
conflicting path; it must not merely set either existing busy flag for a long copy.

Test scope and result
- Six promotions through stock assignment produce newest-four ordering.
- Native option bytes remain unchanged, settings output matches live fields,
  and the uninterpreted tail is preserved.
- Late stock loader failure is detected despite its zero return.
- Failure on pad2 restores pad1's previous loaded sample and empties pad2.
- Save failures restore previous meaningful file contents and session history.
- False success on stock save retry and ignored short/close errors reproduced.
- Snapshot rejects unloaded state or a mismatching runtime path.
- Existing assignment busy boolean demonstrated non-nestable.

reduces mocked boundaries, but the result remains an offline prototype.
