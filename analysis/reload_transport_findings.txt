L6 v1.10 — compiled reload transport endpoints (4 October 2026)

Result
The proposed ownership protocol now has compiled producer, message construction,
consumer, error-observation and return handling. The original reload producer,
worker callback, second UI reload, and settings saver execute on the same
emulated ARM CPU as these adapters. Queue data carries its own ownership tag;
there are no Python FIFO lists pairing separate tags with original messages.
This is an offline replacement-transport experiment, not an installed patch.

Implementation
prototype/overdub/reload_transport.h and .c:
- Runtime 8 bytes; port table 32; task context 64; producer context 16.
- Worker packet 48 bytes = 16-byte envelope plus original 32-byte body.
- UI packet 36 bytes = 16-byte envelope plus original 20-byte event.
- Reserve owner before original 0x80008d68 changes busy state or submits work.
- At original queue send, compiled code adds the worker envelope. Zero send
  result is accepted; nonzero remains uncertain, since delivery is not disproved.
- Consumer copies the whole packet into its task context. Busy admission retains
  it; stale admission consumes the rejected packet without executing stock code,
  allowing the next valid packet. The callback address/event shape are checked.
- Worker runs original 0x80049da0; event publication reserves and includes its UI
  child before sending. UI runs original 0x8002d568, including the second reload
  and actual 0x80006b18 settings-save path.
- Each task has its own context and reentry guard; worker and UI do not share a
  mutable current owner in compiled code. The emulator scheduler explicitly
  selects their contexts when intercepting a boundary.
- After a body returns, error commit and completion are separate retry phases.
  Contention retries metadata without executing stock code a second time.
- Final verification remains external and must follow both returns and joined
  descendants. Successful retirement releases the owner and permits reuse of the
  producer context; no live/faulted context can be reset by this interface.
- Contention during publication faults closed instead of retrying an original
  operation whose effects may already have happened. Recovery remains unbound.

Recovered boundaries used by the emulator
Producer 0x80008d68 -> queue 0x800483f8: original callback word 0x80049da1.
Worker 0x80049da0 -> original event helper -> 0x8006e4b8:
  original UI words [1,4,26,0,0].
UI consumer 0x8002d568 -> 0x80008b68 -> stop/unload/load/save/refresh.
Public file wrappers execute original firmware. Compiled adapters surround the
modeled lower open (0x800604e8), write (0x800624a8) and close (0x8005c388)
boundaries. Their raw status is returned unchanged, but the first error remains
in the task. A short write with a successful raw status is retained as an error.

An expected failure that must not be misclassified
Original settings writer 0x8004b598 calls public open at 0x8004b5d6 with flags 1
(existing file), returning to 0x8004b5da (Thumb LR 0x8004b5db). If open fails, it
tries create with flags 0x101 at 0x8004b5ec. The initial NOT_FOUND result
0xffffd75a is therefore permitted only for this exact caller, UI role and flags.
The entry trampoline model captures the public-open caller per task and passes
it to compiled policy. Other errors at this probe, creation failures, and sample
open failures are retained. The normal test starts without a settings file and
proves successful creation; separate injected failures prove the exception is
narrow. Caller addresses and policy are specific to the verified v1.10 image.

Verification
Run tools/build_overdub_prototype.py then tools/verify_reload_transport.py using
the project Python environment. Fourteen test groups cover original paths,
ignored close failures in both stages, settings short writes/write/close/open
failures, copied-message lifetime, metadata contention, ambiguous delivery and
non-delivery, stale messages followed by valid work, producer reuse, two jobs
with reversed UI delivery, malformed messages, duplicate execution prevention,
unattributed I/O refusal, and failed UI-branch reservation.
All 343 groups across 22 relevant suites pass.
See reload_transport_verification.json for exact cases and fixture boundaries;
reload_transport_regression.json records the relevant suite results and hashes.

Limits and next step
The new packets DO NOT fit the stock queues. Native queue allocation, send and
receive paths, event dispatcher integration, trampoline ABI preservation and
per-task context storage must be recovered and changed together. Existing queues
must drain before a changed ABI could be enabled. The generic original callback
worker loop is replaced by the compiled consumer in this experiment, not patched.
Python still supplies queue copying, scheduler selection, boundary PC/register
redirection, and synthetic filesystem-driver effects. RIFF parsing, audio-engine
prefetch/conversion and RTOS behavior retain the earlier explicit fixtures.
Lower-driver observers do not catch public-wrapper errors before driver entry;
read/EOF policy and other I/O operations are not instrumented here. The compiled
write observer is exercised by the actual settings saver, but durable media and
power-loss behavior are not modeled. Settings readback remains a separate final
verification policy, not an automatic guarantee of this transport test.
Actual async prefetch descendants, USB/card/ordinary-recorder lifetime roots,
and the all-storage fence still need native binding. No new hardware exclusion
or audible playback claim follows from these tests.
The next bounded step is to trace native queue creation and UI-event dispatch to
find where the 32/20-byte message sizes and task lifetimes are set. That will
establish whether enlarged packets are practical or whether a bounded ticket
transport inside the existing message sizes is preferable.
