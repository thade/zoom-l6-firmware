L6 RECORD EVENTS AND ADDITIONAL PRE-MASTER CAPTURE
3 October 2026

Follow-up: record_boundaries_findings.txt qualifies the history branches:
startup clears their flags and selects no lookback; no setter has been found.
It also verifies the saved exclusive stop endpoint through the original writer.

Scope
Keep ordinary clean input files AND processed MASTER in the take folder. The
extra pre-master stereo file remains a distinct recording in a pad folder.
Nothing in this investigation modifies the stock image or accesses the L6.

Result
Six new offline test groups execute original start-cursor and record-control
instructions. They establish that an event-driven start of the extra producer
would not by itself guarantee alignment with ordinary files. The stock recorder
chooses a sample cursor before admission and later applies that saved cursor to
all twelve recording streams, even after the current audio cursor has advanced.
The prior extra-capture and file-lifecycle suites both still pass (11 groups each).

Evidence: tools/verify_record_events.py and analysis/record_events_verification.json

Start selection
0x80034f40 calls 0x80002478 -> 0x80018f10, then stores the result through
0x80006908 at 0x80443154. This happens BEFORE admission/storage checks. A test
rejects the first admission check at 0x80006290 and confirms the start cursor was
still selected/stored, while no start dispatch occurs. Therefore the selector
alone is not a successful-recording notification.

0x80018f10 reads actual flag getters at 0x80010638/658/668. At 48000 Hz:
  flag byte 0x80570c14 == 1: request 24000 earlier samples (0.5 seconds).
  otherwise byte 0x80570c10 == 0 and byte 0x80570c13 == 1:
      request 96000 earlier samples (2 seconds).
  otherwise: no lookback.
The meanings of these flags in the user interface are NOT yet established.
These are reachable instruction branches tested with synthetic state, not a
claim about the current device settings or the normal default mode.

History is clamped to available samples at B+0x53ec, where B=0x20010a48.
The selected cursor is (write_cursor - history) modulo the ring capacity, and is
also stored at 0x80570c0c. Tests cover both history lengths, both no-history
branches, limited/zero availability, ring wrap and 64-bit counter carry.
Original stereo reader 0x80018fd0 returns known historical samples when given
the selected cursor and different current samples at the write cursor.

Backend applies the earlier selection
0x8000b168, when recorder state 0x801f8c48+0xa == 1, calls 0x80006158 to
load the saved cursor, then 0x800381e0 to write all twelve per-stream positions
at 0x8077ca30+0x20 through +0x4c. Tests move the current write cursor forward
640 samples before this backend call, and confirm all twelve positions retain
the earlier selection in each 0/0.5/2-second branch. Scheduler, fade/delay and
file-creation callees are stubbed in this test; it proves the data/control path,
not actual setup latency or a running recording.

Queued start notification is insufficient
0x8004b9a0 invokes 0x8000b650(0) before setting byte 0x80578ebc to 1.
The real b650 returns immediately if recorder state +0x2c is zero, yet the
queued callback still sets the status flag. A synthetic disabled-state negative
control demonstrates this; no claim that normal device operation reaches that
combination. With the state enabled, b650 enables ring copies through 0x80002b50
and reaches backend b168 before setting the UI flag. Deep b168 is stubbed in
this separate test. Neither status observation proves exact sample boundaries.

Stop ordering
0x8004ba40 obtains a cursor through 0x80002460, stores it via 0x80006918 at
0x80443158, calls backend 0x8000b698 with the signed recording target, and later
clears 0x80578ebc. Tests cover ordinary target -1 and pad target 2. The stop
cursor value and backend completion are modeled here. This does not establish
the final included sample, producer quiescence, or pad-reader exclusion.

Design consequence
The extra file needs the same selected start sample as the normal files. Starting
extra_capture when a button/status event occurs is inadequate, even with zero
lookback, because setup can separate selection from the later backend event.

Preserving current stock behavior suggests continuous pre-master history indexed
against the stock audio cursor, then selecting the same start and stop range for
the extra file. It must retain the interval through admission and setup and keep
pace with new audio while the writer catches up. This is a proposed design, not
implemented firmware. A separate option would be a verified common new boundary
for every stream; changing only the extra stream or silently disabling ordinary
history would not satisfy the alignment requirement.

Memory arithmetic, NOT a RAM availability claim
Stereo float32 at 48 kHz uses 384000 bytes per second:
  0.5 seconds = 192000 bytes
  2 seconds   = 768000 bytes
  5 seconds   = 1920000 bytes (matching tested stock ring capacity of 240000)
Current extra buffer: 65536 bytes, approximately 170.7 ms. It is a writer queue,
not a continuous prerecord history, and cannot cover either history branch.
Setup latency and SD stalls require further margin/ownership planning. At the
full five-second size, extra storage is still only hypothetical until the actual
RAM map and competing allocations are established.

Concurrency and assignment
No producer/consumer guard is installed or newly claimed as verified. A draft
generic guard was discarded during this investigation: it could not establish
stock sample alignment, and its rejection path also needed a stronger lifetime
contract. Existing lifecycle functions retain their explicit externally-quiescent
preconditions. No partly tested guard is included in the resulting ELF.

File verification and pad assignment remain separate. Only VERIFIED files may
be considered for assignment; old backing must stay selected until the pad's
actual playback/readers are fenced and the checked assignment/persistence path
succeeds. The earlier pad session's default fence remains unbound and refuses
completion. Record-stop UI state is not a replacement for that fence.

Next bounded investigation
1. Map the three history flags to their setters and operating modes.
2. Establish the shared sample timeline and exact last-sample boundary using
   the saved stop cursor, including ring wrap and queued stop delay.
3. Identify a defensible memory budget for a continuous pre-master history;
   prototype range selection with missing/overwritten-history rejection.
4. Bind scheduling and actual producer/consumer and pad-reader fences only once
   the above contracts are established. Hardware installation/recovery remains
   a separate unresolved requirement.
